# 通用编码规范

适用于所有编程语言和项目的基础规范。

## 基本原则

- 保持代码简洁、可读、可维护
- 遵循目标语言的社区标准编码风格
- 优先使用不可变数据模式
- 编写自解释的代码，仅在必要时添加注释

## 禁止事项

- 不得在输出中包含敏感数据（密钥、token、密码、绝对路径）
- 不得提交未经测试的变更
- 不得绕过安全检查或验证钩子
- 不得无理由地重复已有功能
- 不得在未检查测试套件的情况下提交代码

## 文件组织

- 多个小文件优于一个大文件
- 典型文件 200-400 行，最大 800 行
- 按功能/领域组织，不要按类型组织
- 高内聚，低耦合

## 错误处理

- 在每个层级处理错误
- UI 代码提供用户友好的错误消息
- 服务端记录详细的上下文信息
- 绝不静默吞掉错误

## 输入验证

- 在系统边界验证所有用户输入
- 使用基于 schema 的验证
- 快速失败，提供清晰的错误消息
- 绝不信任外部数据

## 代码质量检查清单

- 函数小（< 50 行），文件专注（< 800 行）
- 嵌套不超过 4 层
- 正确进行错误处理，不忽略返回值
- 不存在硬编码的值
- 标识符可读且命名合理

## 提交风格

- 使用约定式提交：`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`, `perf:`, `ci:`
- 保持变更模块化
- 在 PR 摘要中解释面向用户的影响
